# Plan: Learning Model Demos

## Goal

A set of interactive browser demos that let students and researchers run classic associative learning models and see how each one learns. The sequence starts with Rescorla-Wagner and Mackintosh and builds to MINERVA-AL. Any training design can be run through several models side by side, so it is clear where they agree and where they diverge.

Done means a student can open a page, pick a classic phenomenon such as blocking, run it through each model, and explain from what they see why the models predict what they do.

## Assumptions

These defaults settle the idea's open questions so building can start. Change any of them before Milestone 1.

| Question | Default |
|---|---|
| Audience | Undergraduate and graduate courses first. Accurate enough for researchers to use as a quick sandbox. |
| First models | Rescorla-Wagner, Mackintosh, Pearce-Hall, and MINERVA-AL. A configural model comes later. |
| Format | Standalone web demos in plain HTML and JavaScript, with no build step. R and Quarto versions come later. |
| Home | A new repo, deployed on Coolify with no password, and linked from the lab website. |
| Instance theory of semantics | A later extension, after MINERVA-AL works. |

## Scope

**In**

- One shared framework: a trial-design format, a model runner, charts, parameter controls, and an equation panel.
- Four models with a common interface, each implemented from its published equations.
- Classic phenomena as presets: acquisition, extinction, blocking, overshadowing, conditioned inhibition, latent inhibition, backward blocking, and negative patterning.
- A comparison view that runs one design through several models at once.
- Automated tests that check each model against known results and published simulations.
- Short guided tutorials and exercises for teaching.

**Out, for now**

- Configural models, such as Pearce's configural theory.
- Fitting models to real data.
- The instance theory of semantics.
- R and Quarto versions.

## Milestones

### 1. Framework

- [ ] Create the repo with a plain HTML, CSS, and JavaScript layout and a CLAUDE.md
- [ ] Trial-design format: phases of trial types such as `A+`, `AB+`, `A-`, with repeat counts and optional randomization within a phase
- [ ] Common model interface: `init(params, cues)`, `trial(cues, outcome)`, and `predict(cues)`, plus a `state()` that exposes internal values for display
- [ ] Chart drawn as inline SVG, with no libraries: predicted outcome per cue across trials, with phase boundaries marked
- [ ] Parameter sliders and an equation panel that shows the live values on each trial

### 2. Rescorla-Wagner

- [ ] Summed-error update, with learning rates per cue and per outcome
- [ ] Presets: acquisition, extinction, blocking, overshadowing, conditioned inhibition
- [ ] Presets the model gets wrong, labeled as such: latent inhibition, backward blocking, negative patterning
- [ ] Node tests: the asymptote equals the outcome value, blocking appears, and the overshadowing split matches the analytic result

### 3. Attention models

- [ ] Mackintosh: individual-error learning, and associability that rises for the best predictor of the outcome and falls for the others
- [ ] Pearce-Hall: associability driven by recent surprise
- [ ] Show each cue's associability on its own chart next to its associative strength
- [ ] Tests against worked examples from the original papers or standard textbook treatments

### 4. MINERVA-AL

- [ ] Events as feature vectors for cues and outcome, memory as a matrix of stored traces, and retrieval as an echo weighted by similarity raised to a power
- [ ] Learning as specified in the published model, including its learning-rate parameter, implemented directly from the paper's equations
- [ ] Seedable random numbers and averaging over many simulated learners, since the model is stochastic
- [ ] Visuals: the trace matrix filling up, the echo for the current probe, and similarity per trace
- [ ] Reproduce the key simulation figures from the original MINERVA-AL paper as tests

### 5. Comparison and teaching

- [ ] Comparison view: one design run through all models, overlaid or as small multiples
- [ ] Summary table of which model produces which phenomenon, generated by running the presets, not typed by hand
- [ ] Three to five guided tutorials, for example "why blocking happens" and "where Rescorla-Wagner fails"
- [ ] Deploy on Coolify following the coolify-deploy skill, link it from the lab website, and add it to the course materials

## Risks

| Risk | Mitigation |
|---|---|
| A model is implemented subtly wrong, and students learn the wrong thing. | Implement from the original papers, not secondary sources. Reproduce published results in automated tests before anything is used in class. |
| Notation differs between papers and textbooks, which confuses students. | Pick one notation, show it in the equation panel, and include a short mapping to common alternatives. |
| MINERVA-AL results vary from run to run and are sensitive to its parameters. | Average over many simulated learners by default, show the spread, and keep random seeds fixed for presets. |
| The project grows into a general modeling toolkit. | Keep to the four models and the listed phenomena until the teaching version is in use. |
| Large designs make MINERVA-AL slow in the browser. | Cap trial counts in the interface and keep trace matrices small. Classroom designs are small anyway. |

## First steps

1. Create the repo and write the trial-design format with a parser, tested in Node on the blocking design.
2. Implement Rescorla-Wagner against the common model interface, with tests for asymptote, blocking, and overshadowing.
3. Build the first page: the blocking preset, Rescorla-Wagner sliders, and the SVG chart. Open it in a browser to confirm the shape of the interface before adding models.
